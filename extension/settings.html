Privacy masking



Masking replaces users, hosts, addresses and other identifying values with markers such as ⟦USER#1⟧ before the AI sees them; the real values are restored in the answer on this computer. The popup's privacy switches turn these methods on or off for each case. Your own Hide and Review rules (Custom rules) and credential detection apply even when masking is off.
      









Auto-detect and replace IPs (IPv4 + IPv6), usernames, hostnames, emails, domains, and Windows domain SIDs








Internal IP Ranges



          Private ranges (RFC1918, CGNAT, IPv6 ULA/link-local) are always treated as internal. Add your own CIDR ranges here if your network uses different addressing that should also count as internal.
        



















Internal Domains



          Reserved suffixes (.local, .internal, .corp, .lan, etc.) are always treated as internal. Add your own org-specific domain suffixes here — e.g. an internal AD domain like corp.example.org — so hostnames under it (like lb01.corp.example.org) are skipped instead of sent to threat-intel lookups.

Custom rules


Your own hide, review and keep rules, in one place. A regex rule matches text anywhere in the logs, context and statistics; a field rule matches a JSON field or path. Hide and Review add protection and still apply when the popup's automatic masking is off. Keep stops uncertain values from being flagged, and never overrides a Hide rule, a manual hide or a strong credential.




















Advanced options



















Match mode and Applies to matter for Keep rules: by default a Keep rule must match the whole value, and only uncertain heuristic findings are kept. A field written with dots (_source.tags) is an exact path; a plain name matches that key at any depth.






Test rules on sample text





Uses the rules above before they are saved. Nothing is sent outside this computer.








Credential detection


Recognisable credentials (provider tokens, private keys, authorization headers, passwords in URLs and assignments) are always hidden before anything is sent. Values that only look random, such as long tokens and hashes, are flagged by entropy heuristics and shown for review. The popup's Secret protection switches turn each method on or off.


Entropy thresholds


How random a value must look to be flagged. Raise them to see fewer reviews; lower them to catch more. To stop flagging one field, add a Keep rule in Custom rules.








Threat intelligence



        Reputation and ownership checks for IPs, domains, URLs and file hashes. Secret protection runs before anything is sent to these services. WHOIS / RDAP is free and needs no API key; it supplies registration dates and network ownership where the registry provides them. VirusTotal checks reputation and may supply ASN information. AbuseIPDB checks IP addresses and supplies report counts, ISP, usage type, domain and country. Its documented API does not provide city or WHOIS data.
        
Choose sources in the popup. Automatic enrichment checks up to 50 indicators (25 per type), within a 45-second budget, and caches successful source results for 24 hours. Provider limits can leave partial results; unavailable sources are labelled. Manual Check and Test Keys always request fresh results.

Severity scale

The levels your company or security tools use, from lowest to highest, with the colour shown in the report. The AI picks one when the analyst leaves severity on Auto.








Write {{name}} for each value. Filled by VEILUX: {{title}}, {{case_id}}, {{severity}}, {{date}}. Any other name, such as {{client}}, becomes a field on the report page; a name starting with ai_, such as {{ai_affected_asset}}, is written by the AI instead. Add |upper or |lower to change the case: {{client|upper}}.








How the AI should write: tone, focus, what to include. VEILUX adds the answer format, the language and the severity scale itself. 




Use inline styles: many mail clients ignore <style> blocks. Values: {{title}}, {{case_id}}, {{severity}}, {{severity_color}}, {{detection_time}}, {{date}}, {{summary}}, {{context}}. Lists repeat their block: {{#details}}{{label}} {{value}}{{#highlight}}…{{/highlight}}{{/details}}, {{#risks}}{{.}}{{/risks}}, {{#recommendations}}{{.}}{{/recommendations}}, {{#annexes}}{{label}}{{/annexes}}. Show a section once with {{#has_risks}}…{{/has_risks}}; {{^name}}…{{/name}} shows text when a value is empty. Every value is escaped, so log content cannot add HTML.
